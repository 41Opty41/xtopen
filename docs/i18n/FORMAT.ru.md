# Техническое описание формата Parasolid XT (Clean-Room)

Краткий справочник по структуре файлов передачи Parasolid XT, поддерживаемых в `xtopen`.  
([English version](../FORMAT.md) · [Вернуться к README](README.ru.md))

## 1. Общая структура и текстовый заголовок

Стандартные файлы `.x_b`, `.x_t`, `.x_p` и `.x_d` начинаются с читаемого ASCII-заголовка с секциями `**PART1;`, `**PART2;`, `**PART3;`, который завершается строкой `**END_OF_HEADER`.

- `FORMAT=binary` / `FORMAT=text`
- `GUISE=transmit` / `GUISE=transmit_partition`
- `SCH=...` (идентификатор схемы)
- `USFLD_SIZE=...` (размер пользовательских полей в байтах, обычно `0`)

## 2. Преамбула бинарного и текстового потоков

### Бинарный формат (`.x_b`, `.x_p`, `.x_d`)

Сразу после `**END_OF_HEADER`:
1. Магические 4 байта `PS\x00\x00`.
2. Big-endian `int16` длины + строка моделера.
3. Big-endian `int32` длины + имя схемы (`SCH_...` для Form-2; `sch_...` для Form-1).
4. Для 4-частных имён Form-2 (`SCH_a_b_c`) далее идёт big-endian `int16` `max_node`.
5. Big-endian `int32` `user_field_size`.

### Текстовый формат (`.x_t`)

Физические переводы строк (`\r`, `\n`) в теле потока являются разбивкой по ширине (обычно 78 символов) и удаляются перед разбором токенов.

1. Префикс `'T'`
2. `<len> <ровно len символов>` — строка моделера
3. `<len> <ровно len символов>` — имя схемы
4. Опционально `<max_node>` и `<user_field_size>`

## 3. Коды типов полей и кодирование индексов

| Код | Значение | В бинарном виде | В тексте |
| --- | --- | --- | --- |
| `u` | Беззнаковый байт / перечисление | 1 байт | Целое число |
| `c` | Символ (`+`/`-` ориентация или массив байт) | 1 байт на символ | Символ или строка длиной `varlen` |
| `l` | Логический флаг | 1 байт (`0`/`1`) | `T` / `F` (или `0`/`1`) |
| `n` | Короткое целое | `int16` | Целое число |
| `w` | Беззнаковое короткое целое | `uint16` | Целое число |
| `d`, `t` | 32-битное целое / тег | `int32` | Целое число |
| `p` | Индекс узла-указателя | `i16` (или `i16 + u16`) | `0` = null, иначе 1-базовый индекс |
| `f` | Вещественное двойной точности | `float64` (8 байт) | Число с плавающей точкой |
| `i` | Интервал (2 числа) | 2 x `float64` | 2 числа |
| `v`, `h` | 3-вектор / однородные координаты | 3 x `float64` | 3 числа |
| `b` | Габаритный прямоугольник (box) | 6 x `float64` | 6 чисел |

Сентинелы неопределённых значений в бинарном потоке: `UNSET_I = -32764`, `UNSET_R = -3.14158e13`. В тексте используется символ `?`.

## 4. Form-1 и Form-2: встроенные правки схемы

При первом появлении типа узла `T` в потоке:
- `flag == 255`: раскладка полей совпадает с передаваемыми полями базовой схемы `T`.
- Иначе `flag` задаёт итоговое число полей, а далее идут либо операции правки `C` (копировать базовое поле), `D` (удалить), `I <описание>` (вставить), `A <описание>` (добавить в конец) до маркера `Z`, либо полное встроенное описание нестандартного типа.

Поток узлов завершается записью типа `1` (`NULLP`).

## 5. Геометрические и топологические соглашения

- **Единицы измерения**: все координаты и радиусы в XT хранятся в **метрах**.
- **Конус (`CONE 52`)**: вектор оси направлен *к вершине* конуса (`R(u, v) = P - v*A + ...`), что противоположно направлению `+Z` у `CONICAL_SURFACE` в STEP.
- **NURBS (`126`, `136`)**: рациональные контрольные точки хранятся в однородном виде `[w*x, w*y, w*z, w]` (`vertex_dim=4`), сетка полюсов уложена построчно по `u` (`iu * n_v + iv`). Двумерные p-кривые в области параметров поверхности (`SP_CURVE 137 -> NURBS_CURVE 136`) имеют `vertex_dim=2` `(u, v)` или `vertex_dim=3` `(w*u, w*v, w)`.
- **Контуры и полурёбра (`LOOP 15`, `HALFEDGE 17`)**: цепочка `forward` обходит контур так, чтобы материал грани оставался слева при взгляде со стороны активной нормали грани. Поле `HALFEDGE.vertex` задаёт **конечную** вершину полуребра, а начальная берётся из `backward.vertex`.
